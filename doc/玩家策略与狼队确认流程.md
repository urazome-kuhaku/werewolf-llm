# 玩家策略与狼队确认流程

本文记录 V1 的提示词分层和狼人夜间队内确认边界。它描述的是运行时契约，不把策略建议升级为棋盘规则。

## 提示词分层

每个 Pi 座位启动时收到一份私有系统提示，顺序为：共同决策原则、按可信 assignment.faction_id 选择的阵营策略、当前座位自己的知识导航卡、冻结的规则阅读协议。`role_id` 不参与阵营策略选择，因此角色 ID 叫 `wolf` 但 faction 不是狼人时不会获得狼人策略；反过来，特殊狼角色只要 assignment 的 faction 属于狼人侧就获得狼人策略。未知的 faction ID 会在提示词组合边界被拒绝，旧的无 faction 调用只保留共同原则以维持 API 兼容。

共同原则要求区分引擎事实、玩家声明和推断，比较发言、动机、前后自洽性、投票和替代解释，并用简短的证据到决定摘要更新关键信念。好人策略是职业无关的通用分析；闭合后的公开投票是证据而非证明。狼人策略说明悍跳、冲锋、倒钩、深水的目的与代价，并允许把虚假身份、虚假查验和其他误导作为公开的游戏内声明；这些声明不能覆盖或伪造工具返回、知识收据、引擎状态、权限、已发生行动或不可变审计记录。角色硬规则和技能资源始终以冻结知识快照及只读知识工具为准，发动技能或跳过前读取 `get_skill_status`。

策略 Markdown 和阅读协议都按启动方提供的 SHA-256 读取。`werewolf_reading.md` 是既有 pin，不在本流程中改写。生成的提示文件写入对应会话目录，Pi 进程默认通过 `--system-prompt` 替换其 coding 默认提示；显式使用 `append_system_prompt` 的调用仍可用，但两种模式互斥。

## 白天发言与投票

发言和投票的公开性由游戏事件的 visibility 和阶段关闭边界决定。单个投票在收集期间仍是座位私有输入；窗口关闭只会锁定 ballots，主持人还必须确认结果，确认后引擎才按冻结的 `reveal_after_close` 生成公开结果：`ballots_and_totals` 公开最小的 `voter_seat`、`target_seat`、`weight` 和合计，`totals_only` 只公开合计，`none` 不公开明细或合计。本发布板 `classic_12_seer_witch_hunter_idiot@1.0.0` 的配置是 `visibility_during_collection: secret`，确认后使用 `reveal_after_close: ballots_and_totals`。该策略同样适用于普通投票、PK、警长选举和警长 PK；公开载荷不带请求、运行时、模型或其他元数据，也不把其他座位的私有 ballot、角色、技能资源或队内讨论带入不该看到的观察。

## 狼队讨论、确认与击杀

夜间队聊只在 board 授权的私有窗口中运行。每名符合窗口资格的狼人先提交目标、理由、战术和备选；队内其他人的观点和分歧保持在狼人可见范围。是否强制完成最终计划汇总和确认，由 board 的 `knife_rule.plan_confirmation_required` 独立决定；`classic_12_seer_witch_hunter_idiot@1.0.0` 已启用为 `true`，而 `knife_rule.final_target_required` 独立保持为 `false`，所以最终目标仍可选。所有提案完成后，最终确认者先提交一条私有 `SPEECH`/`TEAM_SPEECH` 最终计划摘要；该 summary 是队内发言，只用于团队沟通和审计，不是工具验证的共识。随后同一座位在独立的结构化行动请求中提交 `WOLF_KILL` 行动码和目标座位；适配器不解析摘要 prose、不从文字选择战术目标、不把 speech 转成 action，也不把摘要当作已经验证的共识。只有引擎在行动边界重新验证授权、窗口、存活目标和资源后，结构化行动才成为待结算请求。计划可以包含目标优先级、白天叙事和被查验或队友出局后的备选，但不能要求模型输出隐藏推理全文，也不能以文本越过行动窗口或伪造引擎事实。

当前适配器从按座位排序的存活狼人中选择首个仍具备 board 授权且本夜 `WOLF_KILL` 可用的座位作为最终提交者；这保证可复现和可恢复，不表示该座位具有更高战术能力、队内地位或官方板子角色。真实 Pi 运行时由策略提示和私有窗口完成讨论，最终仍由引擎验证结构化行动。`night team again` 开启新的讨论代次后，旧代次的最终摘要和计划立即失效，必须重新完成 `night plan next`；每个新的物理夜间窗口都从新的代次开始。`WOLF_TEAM_DISCUSSION_STARTED`、`WOLF_PLAN_STARTED` 和成功/失败请求记录进入持久主持审计，`night plan retry` 复用逻辑请求并创建新的物理尝试，便于恢复而不接受迟到回包。DemoRuntime 等脚本运行时可以忽略策略内容，因此离线测试只证明传输、权限、隐私和清理边界，不证明模型博弈质量。

## 兼容性与限制

旧的追加系统提示字段保留给公共调用方；默认会话改用替换模式，避免 Pi coding 默认提示和狼人杀提示混合。会话失败和正常关闭都会删除临时提示文件，并按 runtime、token、gateway 顺序清理资源。提示层只影响模型的解释和计划表达，不能改变 `GameState`、行动授权、投票结算或技能资源；所有这些仍由序列化的引擎提交路径决定。
