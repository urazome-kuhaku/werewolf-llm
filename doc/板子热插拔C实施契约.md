# C 阶段实施与验收契约

本文件是实施设计，不是完成证据。B 须先完成脚本闭环、恢复及全量检查并提交，然后开始 C 编码。使用技术方案及两份用户规则资料；沿用实施记录中已获授权的实验变体，不虚构网易官方裁定或人工发布审批。

## 通用胜负

- 新包用有类型、有界的条件表达式声明获胜方、条件 ID 和优先级；读取当前存活状态、阵营、胜利组及声明状态，不按角色名或阵营别名执行专属判胜。
- 同时满足多个条件时由显式优先级或声明的平局策略处理，不能依靠 Python 分支顺序。未知引用、不支持表达式及未声明冲突策略在开局前失败。
- 老板子的固定版本兼容结果须保持；新包不能静默退回旧的字符串条件别名逻辑。胜利定义与执行语言进入冻结身份，恢复时核对。
- manager 在触发、规则边界、遗言及警徽未完成时拒绝胜利提交；预算错误不会被判胜掩盖。
- 必测狼美人最后一狼放逐后的魅惑链：所有派生死亡完成，再按实验配置的优先级判定狼方屠边。另测身份四类字段独立变化后的当前阵营与胜利组计数。

## 包生命周期与能力门禁

- 暂存完整版本闭包，校验 schema、依赖、动作和 DSL 能力，编译并实际执行声明式场景后才能原子激活。校验失败保留可定位的覆盖缺口，活动版本不变。
- 相同 ID 的不同版本可并存；同一 ID/版本不同内容拒绝覆盖。下架阻止新局选择，已有局继续使用自有冻结知识、执行计划及动作注册表。
- 活动局引用有持久身份；引用未释放的包不能被卸载。完成局及归档持有的冻结制品不依赖实时目录。失败启动不得遗留错误引用，重试不重复引用。
- 新实验包可在明确的实验命名空间验证和激活；正式知识发布仍沿用现有人工审批流程，不生成假的 reviewer 或 APPROVED 记录。

## 声明式场景和实际运行

- 场景是纯数据，由统一 runner 加载。配置步骤、脚本动作匹配、断言和预算采用封闭类型；不支持 Python 回调、动态导入或板子专属脚本胶水。
- 场景门禁必须实际执行并比较断言，不能仅解析 YAML 或读取一份已写好的 pass 报告。失败场景、无效断言、未消费的必要脚本及预算耗尽都阻止激活。
- 脚本玩家沿真实 Runtime、Gateway 读规则/技能、行动提交、manager 结算路径运行；只消费自己的授权投影。主持器不替脚本读取其他玩家的私有身份来自动选目标。
- CLI 提供可重复的验证入口。整局使用通用开局和 runner，最终完成胜负、关闭、快照和归档校验；实际产物保留在忽略的运行目录。
- 等待玩家选择的持久状态可恢复；循环完成后的快照和归档同时核验执行身份及状态来源。篡改、缺制品、旧版本目录变化均有明确结果。

## 冻结后两板验收

1. C 引擎通过检查并提交，记录冻结提交。
2. 在该提交之上加入两个此前未配置的实验板子包、技能说明、来源及声明式场景。此步只修改规则数据、配置、文档与场景，不改 `src/`、`extensions/` 或全局动作定义，不添加代码插件。
3. 分别跑 12 人整局及关键交互场景。白狼王覆盖非自爆不带人、带猎人允许/禁止枪的实验变体、公共窗口与完整中断边界；狼美人覆盖魅惑过期、空过、决斗抑制与最后一狼魅惑先于胜负；守卫覆盖既定交互变体。
4. 保存运行命令、结果、制品摘要、版本隔离及配置差异证据。若发现引擎缺口，先修正并重新冻结，再重新执行配置验收，不能把修改引擎后的结果算作旧冻结提交的证明。
5. 提交最终包与验收记录到 `werewolf-dev`。真实 Pi 模型行为由项目所有者在本地验收；远端脚本通过不冒充真实模型通过。

## 覆盖矩阵

交付矩阵按已验证的原语、窗口、触发、流程、公开方式和包生命周期列明支持范围。没有实现或没有行为验收的机制标记不支持或待验收；不以两个板子成功推断任意狼人杀规则都可配置运行。

## 现有入口的接入约束

- 当前 `ClassicPlayRunner` 创建 `ModeratorShell`，会话服务已有统一 runtime factory。声明式场景应从这一条开局链路注入通用脚本运行时；保留真实 HTTP Gateway 的规则阅读收据和每次行动前的私有技能查询。场景匹配只读取该座位的 `TurnRequest`、初始本人身份及已授权技能投影，不把 `GameState` 交给玩家选人。
- 必要脚本匹配须记录消费证据，剩余必要步骤不得算通过。默认动作和显式场景动作都经过现有回应协议及权威提交校验；主持操作和整局结果断言另由有界、封闭的场景步骤描述。
- 当前持久快照只允许已审计的循环边界，不能为等待选择而放开原有安全检查。等待选择使用单独的私有检查点类型，校验冻结执行身份、活动 occurrence、窗口、请求和恢复游标；公开循环快照继续拒绝未结算的收集组、待处理触发和规则边界。
- 当前执行制品已随知识包冻结。新胜负定义、场景身份和状态 schema 必须进入对应身份及恢复核验；完整归档从局内冻结制品生成，不能重新读活动目录重算规则。
- 生命周期的暂存、激活、下架和引用管理使用完整版本身份及原子写入。CLI 开局绑定具体已验证版本；恢复已有局使用局内制品，活动版本刷新不能更换其规则。
- 两个声明式新包还须验证首夜死亡、首日警长遮罩、首夜遗言与警徽的真实先后。日间技能的遗言测试不能证明夜间边界也正确；新包不能依靠提前公开遗言或省略已确认的首夜遗言来绕过公共流程。需要延后处理的边界必须有冻结规则及真实流程前置条件，不能由调用方布尔值放行。
